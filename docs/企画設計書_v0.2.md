## 1. ひとことで言うと

単位換算の問題（例：2.5 kg は何 g？）を、速く正確に解き続けるシンプルな計算ゲーム。数値を入力して Enter、の繰り返しで遊ぶ。ゲームとは別に、単位の概要と換算式を見られる「単位表」画面を持つ。

## 2. 方針（v0.2 で決めたこと）

| 項目 | 決定 |
|---|---|
| 立ち位置 | 装飾より「速く解く気持ちよさ」。シンプルな計算ゲーム |
| 入力 | **数値入力のみ**。4択は作らない。PC は Enter 確定、スマホは画面のテンキー。Lv9 以上は「仮数 × 10 の指数」の2枠（§5.3） |
| 分野 | SI基本（長さ・質量・体積・時間・面積）／速さ・温度・圧力・エネルギー・仕事率／ヤード・ポンド法・日本の伝統単位・料理 |
| 除外 | 薬学・看護の分野（mEq、%濃度など）。実在の薬の用量も扱わない |
| 国で値が異なる単位 | **米国式に固定**し、`US` と明示（gallon、cup、pint、quart、fl oz）。英国式は入れない |
| 情報量（B/KB/KiB、Mbps） | 初回公開では見送り。次バージョンの候補（§4.9） |
| 単位の一覧 | ゲーム内の「単位表」画面で見られる（§6） |
| バトル | v0.1 の方針を維持（デイリー → ランキング → 対戦。対戦は反応を見て判断） |

## 3. 遊びの設計

### 3.1 一人用の基本
- 1ラウンド：10問タイムアタック／60秒チャレンジ／練習（時間制限なし）。
- 問題が1つずつ出て、数値を入力して Enter。正誤が即時に出て、次の問題へ。
- 採点：正解数、合計時間、連続正解。誤答は **+3秒のペナルティ**（案）。
- 結果：正答率、平均時間、間違えた問題の復習（正しい換算式つき）、苦手な単位の統計。
- 記録：日ごとの履歴をグラフで表示。

### 3.2 問題の形式
- 形式：`値 [元の単位] = □ [先の単位]`
- 例
  - 2.5 kg = □ g
  - 350 mL = □ L
  - 1.2 時間 = □ 分
  - 3 m² = □ cm²（次元の変換。間違えやすい）
  - 72 km/h = □ m/s
  - 98.6 ℉ = □ ℃（有効数字指定の例：小数第1位まで）
- 答えの形：**割り切れる問題（小数第2位以内で終わる）を基本**とする。時間・接頭辞など SI 同士の換算は、小数第3位が出ない値だけを出題する。ヤード・ポンド法、尺貫法、慣用単位（psi、Torr など）が絡む割り切れない問題は「**小数第2位まで**（その下は四捨五入）」で答える（§5.2）。

### 3.3 誤答時のフィードバック
- 正解と換算式を1行で表示（例：`km → m は ×1000`）。
- 典型的なミスを検出して指摘する。
  - 桁ずれ（正解の ×10、÷10、×100 など）：「桁が1つずれています」
  - 面積・体積の次元の取り違え（例：m²→cm² で 100 と答えた）：「面積は長さの2乗です」
  - 逆方向の換算（×と÷の取り違え）：「掛け算と割り算が逆です」
  - 有効数字指定の問題で最後の桁が±1ずれた：「最後の桁が1ずれています」（§5.3）
- 間違えた単位は出題頻度を上げて復習させる（苦手の統計と連動）。

### 3.4 難易度（レベル 1〜10）
正答率と速さに応じてレベルが上がる。レベルで「出る分野」「接頭辞の範囲」「桁数」「引っかけ」が変わる。

| Lv | 内容 | 例 |
|---|---|---|
| 1 | 基本接頭辞（k, c, m）で長さ・質量・体積。整数中心 | 3 km → m |
| 2 | 時間（秒・分・時間・日）、接頭辞に μ, d, h を追加 | 1.5 時間 → 分 |
| 3 | 小数、桁数が増える。接頭辞 n, M, G | 0.4 mg → μg |
| 4 | 面積（mm²・cm²・m²・a・ha・km²） | 3 m² → cm² |
| 5 | 体積の次元（cm³・m³・L）、料理（大さじ・小さじ・カップ） | 2 L → cm³ |
| 6 | 速さ、温度（℃↔K） | 72 km/h → m/s |
| 7 | ヤード・ポンド法（inch, ft, yd, mile, oz, lb, US gal） | 5 ft → cm |
| 8 | 圧力・エネルギー・仕事率、温度（℉） | 2 kWh → MJ |
| 9 | 日本の伝統単位（尺貫法）、答えを「仮数 × 10ⁿ」の2枠で入力できる問題 | 3 尺 → 寸 |
| 10 | 2段階の換算（接頭辞つき＋別系統）、極端な接頭辞（p, T, P, f など） | 5 mile → km |

> 引っかけの増やし方：見慣れない単位、単位が2段階（例：mL → m³）、桁数の多い値。

## 4. 使用する単位の一覧

### 4.0 一覧の読み方
- 基準単位：各分野で1つ決め、すべての単位を「基準単位に対する倍率」で定義する。分野内のどの2単位間でも `答え = 値 × (元の倍率 ÷ 先の倍率)` で換算できる。
- 倍率は、小数、または有理数（分数）で正確に持つ。浮動小数点は使わない（§5）。
- 区分：**定義**＝定義によって厳密な値／**慣用**＝慣習として決まった値／**注意**＝地域・用途で値が異なるため前提を明示する単位。
- 難度は出題が始まるレベル（§3.4）。
- **系統**：メートル法・SI／ヤード・ポンド法（米国式）／日本の伝統単位（尺貫法）／科学・工学の慣用単位 の4つ。
- **問題で使う係数（v0.2 追記）**：ヤード・ポンド法・尺貫法・慣用単位は、**別系統との換算では有効数字3桁に丸めた係数**を問題に使う（例：1 ft = 0.305 m、1 lb = 454 g、1 尺 = 0.303 m）。実際の正確な値は割り切れないことがあるため、単位表画面と本書の一覧に「正確な値」を注記する。同じ系統どうし（ft↔inch、尺↔寸など）は正確な比を使う。
- 正確な値は下の各表の「倍率」、問題用の3桁係数は §4.10 にまとめる。

### 4.8 温度・圧力・エネルギー・仕事率

#### 温度（倍率ではなく、換算式を持つ）

| 換算 | 式 |
|---|---|
| ℃ → K | `K = ℃ + 273.15` |
| K → ℃ | `℃ = K − 273.15` |
| ℃ → ℉ | `℉ = ℃ × 9/5 + 32` |
| ℉ → ℃ | `℃ = (℉ − 32) × 5/9` |
| K → ℉ | `℉ = (K − 273.15) × 9/5 + 32` |
| ℉ → K | `K = (℉ − 32) × 5/9 + 273.15` |

- 温度差（ΔT）の換算（例：10 ℃ の差 = 18 ℉ の差）は別問題として扱う（Lv8 以降）。
- ℉ → ℃ は割り切れないことがあるため、出題の値は割り切れるものに限る、または「小数第1位まで」指定にする。

## 5. 問題の自動生成

### 5.1 データ駆動
- 単位表（§4）を1つのデータとして持ち、**問題生成と「単位表」画面の両方が同じデータを参照する**。表を直すと両方に反映される。
  ```ts
  type Unit = {
    id: string;            // 'km', 'mmHg' など
    label: string;         // 表示名（多言語に対応できるよう翻訳表に分離）
    dim: string;           // 'length' | 'mass' | 'volume' | 'time' | 'area' | 'speed' | 'pressure' | 'energy' | 'power' | 'temperature'
    toBase: Rational;      // 基準単位に対する倍率（分子/分母を BigInt で持つ）
    kind: 'definition' | 'convention' | 'caution';
    minLevel: number;      // 出題が始まるレベル
    prefixable: boolean;
    note?: string;
  };
  ```
- 温度は倍率ではなく、換算関数（有理数の係数と定数）を別に持つ。
- 同じ `dim` の単位同士だけを組み合わせる。

### 5.2 計算と「きれいな数」
- 問題：`{ value, from, to }`。`答え = value × from.toBase ÷ to.toBase` を **有理数（BigInt）で計算**する。
- 換算には、**同じ系統どうしは正確な比、別系統（ヤード・ポンド法・尺貫法・慣用単位が一方に入る場合）は §4.10 の有効数字3桁の係数**を使う（`problemFactor`）。
- SI 同士の問題は、答えが小数第2位以内で終わる値だけを選ぶ（時間・接頭辞などで小数第3位が出ない）。
- 非 SI の単位が絡む問題は、答えが小数第2位以内で終わればそのまま、終わらなければ「**小数第2位まで答える**」問題とする（答えの絶対値は 0.1 以上、丸めた値が 0 にならないものだけ）。画面に「換算の係数は、単位表の有効数字3桁の値を使います」と注記する。

#### 丸めの規則
- 換算率は丸めず、正確な有理数のまま最後まで計算し、**最後に1回だけ**四捨五入する（途中で4桁に丸めるなどの二重丸めはしない）。
- ちょうど半分の値（例：2.345 → 3桁）は切り上げる。有理数で計算するので、ちょうど半分かどうかを誤差なく判定できる。
- 問題用の係数（有効数字3桁）は、換算の「入力」として最初に決めた値であり、途中で丸めるのではない。その係数での計算結果を、小数第2位で1回だけ四捨五入する。
- 単位表画面には、問題で使う係数と、正確な値（注記）の両方を表示する。

### 5.3 回答の判定
- 数値として等しいか。**有限小数の問題**は常に厳密に一致（有理数で比較）。
- **「小数第2位まで」の問題**は、モードによって判定が異なる。

| モード | 判定 | ずれがあった場合 |
|---|---|---|
| タイムアタック・60秒・デイリー | **厳密一致**：入力を小数第2位に四捨五入した値が、正解（小数第2位に四捨五入）と一致したときだけ正解（例：正解 3.28 に対し 3.279 と入力しても 3.28 になるので正解） | 最後の桁が±1ずれた場合は不正解。「最後の桁が1ずれています（丸めの違いかもしれません）」と表示 |
| 練習 | **±0.01 許容**：最後の桁が±1以内なら正解 | 正解扱い（連続正解は継続）。ただし「ずれあり」と明示する（下記） |

- **ずれの明示**（練習モードで±1を許容した場合）
  - その場で「正解は 3.28。あなたの答え 3.29 は最後の桁が +1 ずれています」と、正解と差を表示する。
  - 結果画面の問題一覧に「ずれあり」マークを付ける。
  - 統計では「完全一致」と「ずれあり」を別に集計する（ずれが多い単位は、丸めの習慣を見直す手がかりになる）。
- 表記の違いを許す：`1,000`、`1000`、`1e3`、全角数字、先頭・末尾の空白、`1000.0`。
- 無入力、数字以外は誤答として扱う（ペナルティなしで再入力でもよい：未決）。

#### Lv9 以上：×10ⁿ の2枠入力（v0.2 追記）
- Lv9 以上では、入力欄が「仮数 ［ ］ × 10 ［指数］」の2枠になる。指数が空欄なら 10⁰ として扱うので、小さい答えは仮数の枠だけに書けばよい。
- 値が同じなら形は問わない（`1.63125 × 10⁴` も `16312.5` も `163.125 × 10²` も正解）。
- 操作：仮数で Enter または Tab → 指数の枠へ、指数で Enter → 決定、Shift+Tab で戻る。指数は整数（−99〜99）。
- 割り切れない問題で答えが 10⁵ 以上のものは、小数第2位ではなく **有効数字3桁**（4桁目を四捨五入）で答える。判定・「ずれ」の扱い（練習は最後の桁±1を許容）は小数第2位の問題と同じ。
- Lv9 以上は、答えが 0.01 未満になる小さな答え（例：1.5 nm → 1.5 × 10⁻⁹ m）も出題する（有限小数であれば桁数は問わない）。
- 答えの表示は、10⁶ 以上、0.001 未満、または有効数字指定の問題で「9.72 × 10¹⁵」の形にする。

### 5.4 シード
- 乱数は `mulberry32` などシード付きの軽い生成器（ライブラリ不要）。
- デイリーのシードは「日付（JST）＋ generatorVersion」。単位表や生成ロジックを直しても過去の日の問題が変わらないよう、`generatorVersion` を保存する。

## 7. 技術設計
- 言語：TypeScript。Vite でビルドし、**静的サイト（Cloudflare Pages など）で公開**。第1段階はサーバーなし。
- PWA 対応（ホーム画面に追加、オフラインでも遊べる）。
- フレームワーク：未決（素の TS／React）。画面数が少なく、単位表の検索と一覧があるため React でも素でも可。
- 保存：`localStorage`（キー `speed-unit-conversion-v1`）。設定、履歴、レベル、ベスト記録、苦手統計。スキーマのバージョンを持ち、**エクスポート／インポート（JSON）**を付ける。
- 多言語：表示名を翻訳表に分離（最初は日本語のみ。英語版は後から追加できる構造にする）。
- テスト（Vitest）：
  - 換算の往復：A→B→A で元に戻る（全ての単位の組）。
  - 既知の値の照合：1 mile = 1609.344 m、1 US gallon = 3.785411784 L など、定義値を別表と突き合わせる。
  - 問題生成：答えが有限小数、同じ次元の単位のみ、シードで再現できる、分布が偏らない。
  - 判定：表記の違い（カンマ、全角、指数）、有効数字指定。
  - 温度：全方向の往復。
  - 典型ミスの検出：桁ずれ、次元の取り違え、掛け割りの逆。

6. 情報量（B/KiB/Mbps）を M2 以降で足すか。
7. フレームワーク（素の TS／React）。
8. フォルダ名の変更（`speed_unit_conversion`）の要否。

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| 地味でやる気が続かない | 連続正解、記録グラフ、自己ベスト更新の表示、デイリー |
| 計算ミス（浮動小数点） | 有理数（BigInt）での演算、定義値の照合テスト |
| 単位の値の誤り（慣用・地域差） | 区分と前提を単位表に明記。定義値は公的な定義と突き合わせてテスト |
| 割り切れない換算で答えが曖昧 | 有効数字指定の問題形式、出題は有限小数に限定 |
| 競合（単位変換アプリは多い） | 変換ツールではなく「速く解く」ゲームに徹する |
| 単位表が見づらい（量が多い） | 分野別タブ、検索、換算式の確認機能 |
| バトルのサーバー費用 | 非同期を先に作る。対戦は反応を見て判断 |
